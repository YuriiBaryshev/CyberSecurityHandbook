## Git: команди для контролю цілісності та автентичності

| Команда | Призначення |
|---------|-------------|
| `git fsck --full` | перевірити цілісність і зв'язність усіх об'єктів репозиторію |
| `git hash-object <файл>` | обчислити геш об'єкта, під яким Git збереже файл |
| `git cat-file -p <геш>` | переглянути вміст об'єкта (коміту, дерева, файлу) за гешем |
| `git config --global commit.gpgsign true` | підписувати всі коміти автоматично |
| `git config --global gpg.format ssh` | використовувати SSH-ключ для підпису замість GPG |
| `git commit -S -m "..."` | створити підписаний коміт |
| `git tag -s v1.0 -m "..."` | створити підписаний тег релізу |
| `git verify-commit <коміт>` | перевірити підпис коміту |
| `git verify-tag v1.0` | перевірити підпис тегу |
| `git log --show-signature` | показати історію разом із результатами перевірки підписів |
| `git reflog` | історія переміщень HEAD — допомагає відновити «втрачені» коміти |
| `git bisect start / good / bad` | двійковим пошуком знайти коміт, що вніс небажану зміну |
| `git blame <файл>` | показати автора та коміт для кожного рядка файлу |
| `git diff <коміт1> <коміт2>` | порівняти два стани й виявити несанкціоновані зміни |

**Порада для захисту гілки main на GitHub:** Settings → Branches → Branch protection
rules → увімкнути *Require a pull request before merging*, *Require signed commits*
та заборонити force push. Так зміни потрапляють у main лише після перевірки,
а історію неможливо переписати.
